# 同舟行前端产品界面体系重建计划

## 0. 已确认方向

产品名称：**同舟行 AI 新媒体运营平台**。

本轮目标不是简单“美化前端”，而是重建前端产品界面体系，让系统第一眼像一个成熟的 AI 新媒体运营平台。

已确认设计决策：

- 默认首页：运营大脑。
- 核心体验：主 Agent 对话输入，编排多个专家 Agent。
- 专家呈现：专业身份卡片，不做真人头像。
- 专家结果：一句核心结论 + 可展开详情。
- 编排节奏：首次唤起有仪式感，后续流转高效清晰。
- 视觉方向：冷白 / 雾白磨砂纸质感，黑白灰极简。
- 登录页：官网首屏型，但克制，不做夸张营销页。
- 布局：升级版左侧固定导航 + 顶部轻工具栏 + 大工作区。
- 第一阶段：全局统一设计风格；重点深做登录页、全局壳层、运营大脑；其他页面先纳入统一风格。
- Agent 编排：先做高保真前端演示流程，但必须预留真实后端 Agent 接口。
- 暂不做：真实投流自动化、真人数字员工、大面积彩色科技风、所有业务页逐页彻底重做。

## 1. 当前问题

1. **第一印象不成立**  
   系统现在更像功能页面集合，不像一个有统一品牌和核心体验的产品。

2. **默认首页不够有力**  
   运营大脑应成为系统核心，但当前首屏还没有表达“主 Agent 调度专家 Agent”的高级感和可信感。

3. **视觉体系摇摆**  
   旧设计仍保留深色金属银方向，和用户当前确认的冷白磨砂纸 + 黑白灰极简方向冲突。

4. **页面布局松散**  
   AppShell、导航、顶部栏、页面标题、面板、表格、状态标记缺少统一规则。

5. **组件语言不精致**  
   按钮、输入框、卡片、标签、表格状态有 Ant Design 默认感和粗糙后台感。

6. **Agent 过程不可感知**  
   用户输入目标后，系统不应只生成结果，而要让主 Agent 调度专家的过程被看见。

7. **其他页面风格不统一**  
   即使第一阶段不逐页重做，也必须先让所有页面进入同一视觉体系，否则仍像半成品。

## 2. 第一阶段交付范围

第一阶段叫：**前端产品界面体系重建 P1**。

范围：

1. 设计令牌与全局 CSS
2. AppShell 全局壳层
3. 左侧导航与顶部轻工具栏
4. 登录页
5. 运营大脑首页
6. 专家 Agent 编排演示流程
7. 专家卡片组件与数据接口预留
8. 基础 UI 组件统一：按钮、输入框、面板、状态、表格外观
9. 其他页面统一套入新视觉体系
10. 本地构建、浏览器检查、部署准备

不在第一阶段深做：

- 账号矩阵业务交互重构
- 小红书 / 视频号真实 OAuth
- 投流真实能力
- 客服真实能力
- 所有页面逐页重新设计业务信息架构

## 3. 分步骤执行计划

### Step 1：文档与设计源头对齐

修改文件：

- `PRODUCT.md`
- `DESIGN.md`
- `SPEC.md`
- `FRONTEND_REDESIGN_PLAN.md`
- `tasks/plan.md`
- `tasks/todo.md`

目标：

- 产品名称统一为“同舟行 AI 新媒体运营平台”。
- 设计方向统一为冷白磨砂纸 + 黑白灰极简。
- 运营大脑定义为默认首页和核心体验。
- 明确专家 Agent 编排先做高保真前端流程，但预留真实接口。

验收：

- 文档不再以深色金属银作为默认方向。
- 文档不再把前端整改描述成简单 UI polish。
- 计划文件能指导后续一步步实现。

### Step 2：设计令牌与全局 CSS 重建

涉及文件预估：

- `frontend/src/theme/tokens.ts`
- `frontend/src/index.css`
- Ant Design theme 配置相关文件

目标：

- 默认浅色主题。
- 黑白灰极简色板。
- 冷白磨砂纸背景。
- 统一圆角、边线、字号、间距、焦点态。
- 移除默认 Ant Design 蓝色痕迹。
- 保留暗色主题能力，但暗色不作为第一阶段默认体验。

验收：

- 登录页和应用内页面默认浅色。
- 文本、占位符、按钮满足可读对比度。
- 没有大面积彩色渐变、光斑、卡片套卡片。

### Step 3：全局 AppShell 重构

涉及文件预估：

- `frontend/src/components/AppShell.tsx`
- 导航配置文件
- 顶部栏相关组件

目标：

- 左侧固定导航：图标 + 文本，不折叠。
- 顶部轻工具栏：搜索、主题、用户、系统状态。
- 主工作区留出运营大脑的大输入与编排流空间。
- 导航层级更像产品，而不是功能列表。

验收：

- 所有页面拥有统一壳层。
- 当前路由状态清晰。
- 投流等暂缓模块不抢占第一阶段主心智。

### Step 4：基础组件统一

涉及文件预估：

- `frontend/src/components/ui.tsx`
- 可能新增 `frontend/src/components/ui/`

目标：

- 重做 `PageHeader`、`Panel`、`StatusBadge`、`PlatformTag` 等基础组件视觉。
- 增加适合专家编排的组件基础：`AgentCard`、`AgentTimeline`、`AgentResultDisclosure`。
- 统一按钮、输入框、表格外观覆盖。

验收：

- 不同页面看起来属于同一套系统。
- 状态表达不只靠颜色。
- 面板不再像粗糙后台卡片。

### Step 5：登录页重构

涉及文件：

- `frontend/src/pages/Login.tsx`

目标：

- 登录页做成克制的官网首屏型入口。
- 明确露出“同舟行 AI 新媒体运营平台”。
- 展示运营大脑 / 专家编排 / 账号矩阵的产品感。
- 移除错误或过时的 demo 账号暗示。

验收：

- 第一眼有品牌和产品感。
- 表单清晰可用。
- 不含夸张宣传、联系方式、最高级表达。

### Step 6：运营大脑首页重构

涉及文件预估：

- `frontend/src/pages/BrainHome.tsx`
- `frontend/src/api/brain.ts`
- 新增或调整运营大脑相关 hook / adapter

目标：

- 页面顶部是 ChatGPT 感的大输入框，但不是聊天应用。
- 输入后进入“主 Agent 编排专家 Agent”的任务流。
- 主 Agent 逐步说明调用谁、为什么调用、当前完成什么。
- 下方专家卡片依次浮现并推进状态。

验收：

- 用户首屏能明确知道可以输入运营目标。
- 编排流能完整演示“主 Agent -> 专家 Agent -> 结论 -> 下一个专家”的过程。
- 专家结果默认一句核心结论，可展开详情。

### Step 7：Agent 编排接口预留

目标：

- 不把演示流程硬编码在页面 JSX 里。
- 抽象出 `AgentOrchestrationAdapter` 或等价数据层。
- 第一阶段使用本地高保真 mock 数据。
- 后续可替换为真实 `/brain/*`、`/agents/*`、WebSocket 或事件流。

建议数据结构：

- `OrchestrationSession`
- `AgentStep`
- `AgentCardState`
- `AgentResultSummary`
- `AgentHandoffMessage`

验收：

- 切真实 API 时不需要推倒 UI。
- 页面组件只消费结构化状态。
- mock 数据能表达启动、进行中、完成、交接、阻塞等状态。

### Step 8：其他页面统一风格

范围：

- 账号矩阵
- 内容流水线 / 任务验收
- 专家团队
- 运营复盘
- 成本
- 风险
- 设置

目标：

- 不逐页彻底改业务结构。
- 统一页面背景、标题、面板、按钮、状态、表格密度。
- 让全站不再像不同系统拼接。

验收：

- 进入任意页面仍能看出同舟行的统一设计语言。
- 未完成能力有明确“等待接入 / 待审核 / 暂未开放”状态，不像系统坏了。

### Step 9：真实浏览器检查

检查项：

- 桌面宽屏
- 1440px
- 1024px
- 768px
- 移动窄屏基础可用性
- 登录页
- 运营大脑输入与专家编排流程
- 账号矩阵页面基础可读性

验收：

- 无明显文字溢出。
- 无按钮挤压。
- 无卡片互相遮挡。
- 控制台无运行时错误。
- 构建通过。

### Step 10：部署准备

目标：

- 本地 build 通过。
- 若用户确认，部署到 `https://dyflow.tzxai.top`。
- 保留回滚点和变更说明。

验收：

- 公网页面可访问。
- 登录页、运营大脑、账号矩阵基本流程可打开。

## 4. 风险与边界

- 第一阶段会改动较多前端结构，但不主动修改后端业务逻辑。
- 专家编排先做高保真前端流程，不承诺第一阶段接真实 Agent 实时输出。
- 因为要统一全局风格，可能会触及多个页面的外观代码。
- 暂缓模块不删除，只降低导航权重或标记为后续。
- 每一步完成后都要能运行，避免一次性大爆改。

## 5. 第一优先级

下一步应先做：

1. 设计令牌与全局 CSS 重建。
2. AppShell 全局壳层。
3. 登录页。
4. 运营大脑首页与专家编排组件。

原因：这四项决定第一印象和核心产品感。账号矩阵已经能接入抖音，下一轮再做业务交互深改会更稳。
