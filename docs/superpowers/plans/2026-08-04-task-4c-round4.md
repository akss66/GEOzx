# Task 4C Round 4 Plan

## Global lock policy

Every path that can touch a runtime-owned deliverable uses one acyclic order:

`ContentItem -> AgentRun -> ConversationTurn -> BrainTask -> parent SkillRun -> child SkillRuns by id -> RunRevision -> Deliverables by id -> AgentToolCalls by id`

Read-only ID discovery runs under `session.no_autoflush`; no mutation or flush is allowed before the first required lock.

| Path | Required locks and transaction owner |
|---|---|
| child/parent deliverable write then close | Content first in `write_runtime_deliverable`; close continues Content -> Run -> Turn -> Task -> exact SkillRun; runtime caller owns commit |
| artifact accept / dependency pause | Content -> Run -> Turn -> Task -> parent -> children -> Deliverables; artifact API owns commit and rechecks approval under lock |
| nested finish approve/reject | Content -> Run -> Turn -> Task -> parent -> children -> Deliverables -> ToolCall; approval API owns one commit and post-commit publish |
| cancel / revision cancel | Content -> Run -> Turn -> Task -> active parent/children -> RunRevision; terminal SkillRuns/receipts are never selected or mutated |
| reject helper | Acquires/validates the same composite scope itself, then mutates child+parent in the caller-owned transaction |
| ordinary non-composite close/approval | Content -> Run -> Turn -> Task -> exact active SkillRun; legacy commit behavior remains the default |
