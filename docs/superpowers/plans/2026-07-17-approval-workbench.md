# P5 人工审批工作台实施计划

## 目标

将旧纵向审批卡片页重构为真实、可审计、按资源授权的三段式桌面审批台。审批对象统一来自质量门、Agent 工具权限和正式成果验收，不制造前端假队列。

## 后端

1. 新增 `GET /approvals/workspace` 聚合接口，接受 `client_id`、`project_id`、`account_id` 可选上下文。
2. 统一返回审批类型、项目、账号、内容、任务、风险等级、风险原因、影响范围、Agent 解释和类型化预览数据。
3. 质量门、工具调用和成果验收只返回当前用户可访问客户/项目内的数据。
4. 负责人和审核员可决策；编辑与普通运营只能查看，无权审批。
5. 修复既有质量门和工具审批接口仅按组织过滤的问题，并保留原接口兼容。
6. 发布、账号授权、删除和外部平台动作固定为高风险或关键风险，不允许自动通过。

## 前端

1. 左侧：待审批队列、类型与风险筛选、等待时间和项目/账号上下文。
2. 中间：根据审批对象展示完整成果文档、发布包或工具影响，不显示原始 JSON、内部模型名。
3. 右侧：风险等级、原因、影响范围、Agent 解释、修改意见和操作。
4. 驳回必须输入修改意见；正式成果使用“驳回并重跑”。
5. 审批完成后刷新真实队列并自动定位下一项。
6. 空状态仍保留三段式工作台骨架，不使用巨大插画或假数据。

## 验收

1. 普通成员无法看到未授权项目审批。
2. 审核员可以处理授权项目审批，编辑不能处理。
3. 三类审批均能在同一工作台预览和处理。
4. 发布包完整展示账号、素材、封面、话题、排期、可见性、评论和人工步骤。
5. 驳回无意见时不提交；提交后状态更新并自动切换下一项。
6. 前端全量测试、生产构建、后端相关 pytest、Ruff 和 1440px 桌面浏览器验收通过。
