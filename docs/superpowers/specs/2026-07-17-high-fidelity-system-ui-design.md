# 同舟行全系统高保真 UI 基准

> 状态：用户已确认
> 日期：2026-07-17
> 适用范围：全部桌面端页面

## 1. 唯一视觉基准

全系统以用户确认的运营大脑高保真稿作为唯一视觉母版。它不是只属于运营大脑的页面方案，而是系统级产品语言：暖纸导航框架、柔白工作画布、墨黑排版、克制品牌红、细线分隔、低阴影和明确留白。

旧的灰白 SaaS 后台、卡片墙、技术面板堆叠和各模块独立主题不再作为设计依据。现有后端能力、真实数据和业务结构继续保留。

## 2. 全局骨架

- 桌面端左侧固定 `248px` 暖纸导航栏。
- 顶部工作栏承载客户、项目、平台、账号、搜索、通知和帮助。
- 主工作区使用柔白画布，不使用整页灰底卡片网格。
- 客户与项目在左上切换，平台与账号在顶部明确选择。
- 未明确选择账号时，业务页面不得隐式使用第一个账号。
- 运营大脑页面不重复显示右下角全局主 Agent 入口；其他页面保留该入口。

## 3. 视觉令牌

- 品牌框架：`#EEE8DF`
- 工作画布：`#F7F7F4`
- 高对比表面：`#FFFFFF`
- 主文字：`#171614`
- 次文字：`#4A4640`
- 分隔线：`#DDD8CF`
- 品牌红：`#C9161D`
- 控件圆角：`8px`
- 独立对象圆角：`10px`
- 浮层圆角：`12px`

阴影只用于浮层、输入悬浮区和需要脱离画布的对象。页面章节默认使用留白与细线组织，不使用卡片墙。

## 4. 页面适配

### 运营大脑

- 空状态使用中央主 Agent 问候和大输入区。
- 不显示常驻 Dashboard、右侧状态栏或多余页面标题栏。
- 对话、专家接力、正式成果和人工确认都进入同一对话流。
- 输入区在对话态固定于工作区底部；权限请求到来时输入器原位切换为紧凑确认模式，方案选择则作为结构化内容留在对话流中。

### 账号矩阵

- 保留表格、矩阵、账号卡和项目四种视图。
- 以高密度工作台呈现，平台状态和账号状态使用文字、图标与轻量色彩，不使用大面积彩色卡片。

### 内容生产

- 保持文档画布为视觉中心。
- 素材、版本、Agent、审批与发布准备按需展开，不把全部工具常驻成卡片。

### 人工审批

- 保持队列、预览、判断三段式结构。
- 风险信息使用细线、标记和局部语义色，决策按钮保持墨黑主动作。

### 运营复盘

- 以结论、变化、归因、证据、建议的报告叙事组织。
- 图表只承担证据角色，无数据时解释真实缺失原因。

### 专家、知识、成本与管理页面

- 使用编辑部目录、文档画布、账本和检查器等对应工作模式。
- 共用同一字体、色彩、间距、表面、控件和状态语言。字体固定为随应用打包的 `Geist Variable + Noto Sans SC Variable`，不依赖用户电脑是否安装特定字体。
- 管理页面允许更高信息密度，但不得回到通用后台模板感。

## 5. 验收标准

- 仅验收桌面端 `1280px`、`1440px`、`1920px`。
- 所有页面共享同一 App Shell 和视觉令牌。
- 无横向溢出、遮挡、重复入口或不可读文本。
- 普通用户不看到原始 JSON、内部模型名或技术状态。
- 空状态、错误、加载和权限阻断状态均有明确业务解释。
- 每个模块在 localhost 经用户验收后才能部署线上。
