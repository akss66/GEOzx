# 导入批次永久删除设计

> 状态：用户已确认
> 日期：2026-07-27

## 1. 背景与目标

账号数据中心目前支持查看导入历史、下载原文件，以及撤销已确认批次，但没有永久删除能力。误上传文件、已撤销批次和不再需要保留的历史批次因此会持续占用导入历史与文件存储。

本次改动为所有导入批次提供受控的永久删除能力。删除操作覆盖批次元数据、原始文件、预览行、冲突记录，以及该批次产生的正式数据。操作不可恢复，且不得连带删除或修改其他批次。

## 2. 已确认的产品决策

- `uploaded`、`preview_ready`、`failed`、`revoked` 和 `committed` 状态均允许发起永久删除。
- 删除已确认批次时，系统自动执行与“撤销导入”等价的数据清理，再删除批次。
- 如果目标批次已被后续批次覆盖、引用或形成撤销冲突，则阻止删除并返回明确提示。
- 不级联删除后续批次，也不提供强制绕过关联检查的入口。
- 永久删除仅允许当前账号工作区的负责人执行，与现有撤销权限保持一致。
- 删除前必须二次确认，并明确说明操作不可恢复及其影响范围。

## 3. 后端接口与权限

新增接口：

```text
DELETE /account-data/{account_id}/imports/{batch_id}
```

成功响应使用 `204 No Content`。接口先通过现有账号访问控制验证组织、账号和负责人角色，再按组织、账号和批次三重作用域加载目标，避免跨账号删除。

错误语义：

- `404`：目标批次不存在或不在当前作用域。
- `409`：目标批次存在后续覆盖、引用或其他撤销冲突。
- `403`：当前成员不是负责人。
- `500`：数据库或文件清理发生不可恢复的内部错误；服务端记录诊断信息，但不向响应泄露存储路径。

重复请求在首次成功后返回 `404`，前端将其视为目标已不存在并刷新列表，不继续显示已删除批次。

## 4. 删除服务与数据流

新增单一服务入口 `delete_batch_permanently`，复用现有批次作用域、撤销冲突检查和投影删除逻辑，避免 API 层复制业务规则。

处理顺序：

1. 在事务中锁定并加载目标批次及其原文件、行和冲突。
2. 对已确认批次执行现有撤销冲突检查。
3. 若存在后续覆盖或引用，终止操作，不修改任何数据或文件。
4. 对可删除的已确认批次，删除该批次产生的正式投影；其他状态跳过此步。
5. 收集原文件存储键，并将文件原子移动到同一存储根下的隔离位置。
6. 删除批次记录；数据库级联删除其原文件元数据、预览行和冲突记录。
7. 提交数据库事务后，彻底删除隔离文件。
8. 如果数据库提交失败，将隔离文件恢复到原位置并回滚事务。

隔离目录只能位于受控存储根内，路径必须继续通过现有 `storage.resolve` 约束。清理空目录属于尽力而为，不影响删除结果。

数据库提交成功后若最终文件清理失败，业务数据仍保持已删除状态；服务端记录清理失败，保留隔离文件用于运维清理，避免重新暴露为可下载文件。

## 5. 前端交互

每个导入历史卡片增加“永久删除”危险按钮。按钮对所有状态显示，但后端仍是最终权限边界。

点击后在当前卡片内显示二次确认区域：

- 待导入、失败、已撤销批次：提示将永久删除批次、预览数据和原文件。
- 已确认批次：额外提示会先撤销该批次产生的数据。
- 提供“确认永久删除”和“取消”两个按钮。
- 删除进行中禁用同一卡片的查看、下载、撤销和删除操作，并显示加载状态。

删除成功后：

- 清除该批次的详情缓存。
- 刷新导入历史和账号数据状态。
- 若删除的是当前批次，选择刷新后列表中的首个待处理批次；没有批次时回到空状态。
- 显示简短成功反馈。

删除失败时保留卡片和当前选择，在导入历史区域显示后端返回的安全错误信息。关联冲突提示应说明该批次存在后续数据，不能永久删除，不提供级联确认。

## 6. 测试策略

后端测试覆盖：

- 负责人可删除待导入、失败和已撤销批次。
- 删除会移除数据库批次图及物理原文件。
- 删除已确认批次会先清理其正式投影。
- 存在后续覆盖或引用时返回 `409`，数据库和文件均保持不变。
- 操作员和只读成员不能永久删除。
- 组织、账号或批次作用域不匹配时不能删除。
- 数据库提交失败时恢复已隔离文件。

前端测试覆盖：

- 所有状态均显示永久删除入口。
- 二次确认文案按已确认与其他状态区分。
- 确认后调用正确的 `DELETE` 接口。
- 成功后清除详情缓存、刷新历史和状态，并正确重选当前批次。
- `403`、`409` 和通用错误均显示可理解的反馈。
- 删除进行中交互被禁用，取消不会发起请求。

端到端验收覆盖上传待导入文件、永久删除、历史记录消失且原下载地址不可再访问；另覆盖已确认批次自动撤销后删除。

## 7. 非目标

- 不支持批量永久删除。
- 不支持删除单个原文件而保留批次。
- 不支持恢复已永久删除的批次。
- 不支持绕过后续关联检查或级联删除其他批次。
- 不改变现有“撤销导入”能力；需要保留审计记录时仍应使用撤销。
