# 运营大脑对外称谓统一设计

## 目标

将产品中所有面向用户的“主 Agent”称谓统一显示为“运营大脑”，使导航名称、欢迎区身份、消息流、操作提示和运行状态保持一致。

## 命名边界

### 对外统一为“运营大脑”

- 前端可见标题、正文、按钮、占位符、通知和空状态文案。
- 前端无障碍名称，包括 `aria-label` 和头像替代名称。
- 后端返回给用户的运行状态、事件消息、错误提示、操作项和 Agent 展示名称。
- 模型面向用户生成的回复称谓。
- 历史任务中由系统生成、可能仍包含“主 Agent”的展示文案。

### 内部继续使用“主 Agent”

- `00-decision` 等稳定 Agent code。
- 组件名、函数名、变量名、文件名、CSS 类名和数据库字段。
- Prompt 中用于描述架构职责和调度关系的内部角色概念。
- 技术文档、设计文档和开发注释。
- 用户自己输入或保存的原始内容。

## 实现方案

### 前端静态文案

逐项修改产品界面中的静态“主 Agent”文案，包括运营大脑首页、输入区、方案选择、专家编排、全局入口、专家成果交接、配置页、复盘页和登录页。

头像组件对 `00-decision` 的默认无障碍名称改为“运营大脑”，调用方仍可通过显式 `label` 覆盖。

### 后端系统文案

修改 API、运行时、智能判断错误、规划结果和专家工作区中会返回给前端的系统文案。新的任务、事件和运行状态从源头写入“运营大脑”。

内部异常类型、调度代码和角色结构不重命名。

### 模型生成内容

主 Agent 的内部职责仍以“主 Agent”描述，但面向用户的 Prompt 增加统一称谓约束：自称或指代自身时使用“运营大脑”，不向用户展示“主 Agent”这一内部架构术语。

### 历史数据兼容

仅在渲染受信任的系统字段时，将历史文案中的“主 Agent”规范化为“运营大脑”。规范化不得用于用户消息、用户备注或其他用户原始内容，避免篡改用户表达。

## 数据流

1. 新系统文案在前端或后端源头直接使用“运营大脑”。
2. 后端任务与事件通过现有 API 返回，不改变数据结构。
3. 前端对旧任务的系统状态、系统事件和 Agent 展示名执行有限的称谓规范化。
4. 用户原始输入沿现有链路原样展示。

## 兼容性与风险

- 不改变 API 字段、Agent code、数据库结构或路由，不需要数据迁移。
- 不进行无边界的全局字符串替换，防止修改用户消息、技术语义和历史文档。
- 当前工作区存在未提交的 AI COO 改动；实施时只修改目标字符串附近内容，并单独暂存本次文件。
- 长文案替换后可能产生换行变化，需在欢迎态、对话态和全局入口进行浏览器验收。

## 测试与验收

1. 欢迎区头像旁显示“运营大脑”。
2. 消息流、输入区、方案选择和全局入口不再显示“主 Agent”。
3. 专家编排、成果交接、配置、复盘和登录页使用“运营大脑”。
4. 后端新生成的运行状态、事件、错误和操作项使用“运营大脑”。
5. 历史系统文案中的“主 Agent”在界面显示为“运营大脑”。
6. 用户自己输入“主 Agent”时，消息内容保持原样。
7. `00-decision`、头像资源和业务行为不变。
8. 相关前后端测试、前端生产构建和浏览器验收通过。

## 非目标

- 不重命名内部主 Agent 架构角色。
- 不修改 Agent code、接口字段、数据库表或迁移文件。
- 不批量改写历史数据库记录。
- 不修改技术文档中对主 Agent 架构的说明。
