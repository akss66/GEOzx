# 主 Agent V2 交接说明

更新时间：2026-07-29

## 当前结论

主 Agent V2 整改计划的开发、回归验证和独立审查已经完成。本地候选版本以
`86f97ae fix: reject cross-task agent deliverables` 为基线，后续 cost 账本收口与本文档
更新将在发布候选分支单独提交。

本轮已完成的核心能力包括：

- 主 Agent 作为唯一用户入口，按意图选择回答、查询、Skill、任务或动作链路。
- Skill 负责编排专家 Agent 与 Tool，专家正式产出与主 Agent 汇总职责分离。
- 对话 Thread、Turn、AgentRun、SkillRun、任务和成果具备可追踪的来源关系。
- 普通诊断不再固定进入完整策略图，用户明确不要策略时不会生成 Strategy。
- 专家执行前的项目与账号作用域校验、业务冲突分类、不可重试错误收口已经修复。
- 业务冲突不再被 Worker 重试三次；消息、事件和成果具备幂等边界。
- 专家未实际执行时，前端不会伪装成“正在调用专家”。
- AgentRun、BrainTask 与 Turn 的终态保持一致，失败任务不再长期停留在 running / 0%。
- 工具结果可以进入专家链路，正式成果具备专家、证据、验收和技术日志来源。
- 当前轮次只展示当前轮次的策略、成果和状态，避免历史任务污染新消息。
- 账号、项目、用户和任务来源关系经过服务端校验，拒绝跨账号或跨任务成果挂载。
- 成果同时保留在产生它的对话消息下，并进入统一成果中心。

## cost 账本收口

本次发布候选额外收口以下成本问题：

- 主 Agent 没有 AgentInvocation 的模型调用也会进入业务成本账本。
- 有 LLMCall 明细的专家调用不再与 AgentInvocation 估算成本重复计费。
- 主 Agent 同一任务中的多次底层模型请求按一次业务操作计数，重试不会虚增调用次数。
- 成本先按原始精度累加，最终展示时统一四位小数，避免逐条舍入造成漏记。
- 成本查询继续遵守组织、客户、项目和账号访问范围。
- DeepSeek V4 Pro、V4 Flash 及兼容别名采用当前公开价格。

业务页面中的“专家调用”只统计专家 Invocation。主 Agent 调用会进入成本金额和
“按专家与工具归因”中的“运营大脑”条目，但不会冒充专家调用次数。

## 生产发布约束

- 使用新的不可变 release 目录，不覆盖现有生产目录。
- 发布前备份数据库并记录当前 migration revision、Compose 状态和回滚目录。
- Main Agent V2 数据库迁移为增量迁移；应用回滚时保留新表和来源数据，不直接执行
  schema downgrade。
- 首选回退手段是关闭 `main_agent_v2_enabled` 并回到旧应用版本。
- 首批流量只允许管理员和指定账号；扩大到普通成员前需要独立验收。
- 健康检查、迁移检查、关键 API 和浏览器验收任一失败，都应停止扩大流量并回滚应用。

详细步骤见 `docs/runbooks/main-agent-v2-rollout.md`。

## 生产验收重点

至少验证以下链路：

1. 登录与工作区加载正常。
2. 账号资料与账号数据上下文可读取。
3. 普通问答不会启动不必要的完整运营图。
4. “只做账号诊断、不生成策略”只产生诊断成果。
5. 专家真实执行时产生 AgentInvocation，并在消息下显示专家与成果来源。
6. 业务冲突只返回一次可操作错误，不重复回复、不进入死信重试。
7. Turn、AgentRun、BrainTask 和成果最终状态一致。
8. 不同账号之间的对话上下文、任务和成果互不可见。
9. cost 页面包含主 Agent 模型费用，并且没有重复计费。

## 后续工作

以下内容不属于本次生产发布：

- 历史对话抽屉和真正的新建 Conversation Thread。
- 用户永久删除自己的对话消息与技术执行日志。
- 删除对话后保留正式成果、已采纳内容、任务、策略、复盘和经验，并解除来源链接。
- 运行中的对话禁止删除；当前对话删除后返回空白新对话。

该功能继续遵守已经确认的产品边界：

- 历史对话按用户和账号双重隔离。
- 所有人只能删除自己的对话，管理员也不能删除其他人的对话。
- 永久删除采用普通二次确认，不要求输入确认文字。
- 对话内成果与成果中心两处都能找到正式交付物。
